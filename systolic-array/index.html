Reconfigurable systolic array accelerator

2026

SystemVerilog, RV32I, memory-mapped I/O, FPGA DSP blocks

Most of the work in a neural network layer is matrix multiplication. A systolic array does it with a grid of multiply-accumulate (MAC) units that pass operands to their neighbours every cycle, so each value fetched from memory gets reused many times.

A typical array's behaviour is fixed when it's synthesized. I wanted one where the dataflow, the arithmetic precision and the matrix size could all be changed from software while it runs, so I built the array, its MAC units, and a small RISC-V processor to control it, all in SystemVerilog.

Three dataflows, one array

There are three common ways to schedule a matrix multiply on a systolic array, depending on which operand stays put in each processing element:

  • Weight stationary: each element holds a weight while the inputs stream past it.
  • Input stationary: each element holds an input while the weights stream past it.
  • Output stationary: each element keeps its own partial sum and accumulates in place.

Each processing element has multiplexers in front of its operand and partial-sum paths. A configuration setting picks which way the data is routed, so the same hardware runs all three dataflows and can switch between them at run time.

Two precisions in the same multipliers

The MAC units are built on the FPGA's variable-precision DSP blocks and use sub-word parallelism: the same hardware can run one 32-bit operation or two 16-bit operations side by side. The chip has a fixed budget of 174 hardware multipliers, so switching to 16-bit mode doubles the number of multiplications done per cycle when the lower precision is good enough.

A processor to drive it

To control the accelerator I wrote a single-cycle RV32I core in SystemVerilog and mapped the accelerator's control registers into its address space. A program sets the dataflow, the precision and the matrix dimensions, then starts the computation, using nothing but ordinary load and store instructions. No custom instructions or special compiler support are needed.
